gRPC - Remote Procedure Call - **фреймворк для удалённого вызова процедур.

- используется для обмена данными между сервисами, особенно в микросервисной архитектуре для высокой производительности
- gRPC позволяет разным сервисам (или клиентам и серверам) вызывать методы друг друга так, будто они находятся в одной программе, даже если они написаны на разных языках и работают на разных машинах.
- общение в бинарном формате данных, (не xml, json...)
- позволяет вызывать методы как локальные функции, поддерживает стриминг в обе стороны




## Основные особенности

| ВИД                        | ОПИСАНИЕ                                                                                                                                                                                                                                                                                |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Транспорт                  | HTTP/2 (быстрее, мультиплексирование, сжатие заголовков, поддержка потоков)                                                                                                                                                                                                             |
| Формат данных              | Protocol Buffers (Protobuf) — бинарный, компактный, сильно типизированный формат (гораздо меньше размер и быстрее парсинг, чем JSON)                                                                                                                                                    |
| Сильная типизация          | всё описывается заранее в .proto файлах → компилятор генерирует код клиента и сервера на 10+ языках (Go, Java, Python, C#, Node.js, Rust и т.д.)                                                                                                                                        |
| Четыре типа взаимодействия | 1) Unary (классический request → response, как в REST)<br>2) Server streaming (один запрос → поток ответов от сервера)<br>3) Client streaming (поток запросов от клиента → один ответ)<br>4) Bidirectional streaming (оба потока одновременно — клиент и сервер шлют данные независимо) |

### Когда выбирать gRPC (реальные сценарии)
- Микросервисы внутри одной компании (внутренние сервисы) — особенно если нужна максимальная производительность и низкая задержка
- Реал-тайм коммуникация (streaming данных: чаты, мониторинг, IoT, стриминг событий, телеметрия)
- Многоязычная среда (сервисы на Go, Java, Python, C# и т.д. должны общаться между собой)
- Системы с высокой нагрузкой (Netflix, Uber, Square, Cisco, Dropbox — используют gRPC)
- Когда размер трафика критичен (мобильные приложения с ограниченным трафиком)

### Когда REST всё ещё лучше
- Публичные API (для внешних разработчиков, браузеров)
- Простота и быстрая разработка (Swagger, Postman — всё готово)
- Когда нужна человеческая читаемость (JSON)
- Legacy-системы или когда команда не готова изучать Protobuf + codegen

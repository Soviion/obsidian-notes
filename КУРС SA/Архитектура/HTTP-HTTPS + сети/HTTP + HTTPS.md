HTTP (HyperText Transfer Protocol) — это протокол прикладного уровня, работающий по модели клиент-сервер. Он stateless (не сохраняет состояние между запросами) и обычно использует TCP-соединение.

TCP — Transmission Control Protocol (Протокол управления передачей)- это протокол транспортного уровня, который обеспечивает **надёжную, ориентированную на соединение** передачу данных между устройствами в сети.
- Делит данные на пакеты, нумерует их, проверяет на ошибки и собирает в правильном порядке на приёмной стороне.
- Гарантирует доставку (повторная отправка потерянных пакетов), контроль потока (чтобы не перегружать приёмник) и управление перегрузкой.
- Основной процесс установления соединения — **3-way handshake** (трёхэтапное рукопожатие): SYN → SYN-ACK → ACK.

Основной цикл работы HTTP:
1. Установка TCP-соединения: 
	Клиент (браузер) устанавливает TCP-соединение с сервером (по порту 80).
2. Клиент отправляет запрос (Request): 
	структура запроса:
	- Стартовая строка: Метод (GET/POST и т.д.) + URI + версия HTTP (например, GET /index.html HTTP/1.1).
	- Заголовки (Headers): Host, User-Agent, Accept, Cookie и т.д.
	- Тело (Body): Опционально, например, данные формы в POST.
3. Сервер обрабатывает запрос: 
	Парсит запрос, выполняет логику (например, читает файл или запускает скрипт).
4. **Сервер отправляет ответ (Response)**:
	- Стартовая строка: Версия HTTP + код статуса (например, HTTP/1.1 200 OK).
	- Заголовки: Content-Type, Content-Length, Set-Cookie и т.д.
	- Тело: HTML, JSON, изображение и т.д.
5. Завершение: 
	Соединение может закрыться или остаться открытым (keep-alive в HTTP/1.1).
	
Всё передаётся в открытом текстовом виде — любой на пути (провайдер, роутер) может прочитать данные.


# HTTPS

HyperText Transfer Protocol Secure — это HTTP поверх шифрования TLS/SSL. Основное отличие: перед обменом HTTP-данными происходит TLS-handshake (рукопожатие), которое устанавливает безопасное соединение.

TLS/SSL — Transport Layer Security / Secure Sockets Laye
- Обеспечивает шифрование, аутентификацию сервера (через сертификаты) и целостность данных.
- Работает между транспортным (TCP) и прикладным (HTTP) уровнями.
- Основной процесс — **handshake** (рукопожатие): обмен ключами, проверка сертификата, установка сессионного ключа.
- SSL устарел (версии 1–3 небезопасны), теперь все говорят TLS, но часто называют "SSL" по привычке (например, SSL-сертификат).

**Полный процесс HTTPS:**
1. **Установка TCP-соединения**: 
	Как в HTTP, но на порту 443.
2. **TLS Handshake** (установка шифрованного канала):
    - **Client Hello**: Клиент отправляет поддерживаемые версии TLS (1.2/1.3), шифры, расширения.
    - **Server Hello**: Сервер выбирает версию и шифр, отправляет свой сертификат (с публичным ключом).
    - **Проверка сертификата**: Клиент проверяет сертификат через цепочку доверия (CA, как Let's Encrypt).
    - **Обмен ключами**: Генерируется симметричный сессионный ключ (обычно с ECDHE для perfect forward secrecy).
    - **Finished**: Обе стороны подтверждают, что handshake завершён.
    После этого весь трафик шифруется симметричным ключом (быстрее асимметричного).
3. **Обмен HTTP-данными**: 
	После handshake запросы и ответы HTTP идут так же, как в обычном HTTP, но **в зашифрованном виде**.
4. **Завершение**: 
	Соединение закрывается или используется повторно.

TLS обеспечивает: конфиденциальность, целостность и аутентификацию сервера.

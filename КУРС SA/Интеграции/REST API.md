Основные ограничения - принципы REST:
1. **Client-Server** – разделение клиента и сервера.
2. **Stateless** – сервер не хранит состояние клиента между запросами.
3. **Cacheable** – ответы могут кэшироваться для оптимизации.
4. **Uniform Interface** – единообразный интерфейс (HTTP методы, URI, медиа-типы).
5. **Layered System** – система может состоять из слоёв.
6. **Code-on-Demand (опционально)** – сервер может отправлять исполняемый код.

| 1. Client-Server                        | Разделение обязанностей между клиентом и сервером: <br>клиент — отвечает за пользовательский интерфейс и пользовательский опыт, <br>сервер — за хранение данных и бизнес-логику. → Это позволяет развивать их независимо (клиент можно обновлять без перезапуска сервера и наоборот).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 2. Stateless (Без сохранения состояния) | Каждый запрос от клиента должен содержать всю необходимую информацию для его обработки — сервер не хранит состояние клиента между запросами (нет сессий на сервере). <br>→ Увеличивает масштабируемость: любой сервер может обработать любой запрос.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 3. Cacheable                            | Ответы сервера должны явно указывать, можно ли их кэшировать (через заголовки Cache-Control, ETag и т.д.), и на какой срок. <br>→ Клиенты/промежуточные прокси могут повторно использовать ответы <br>→ снижается нагрузка на сервер и задержка.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 4. Uniform Intarface                    | Единый способ взаимодействия с ресурсами через:<br>- Идентификацию ресурсов (URI)<br>- Манипуляцию ресурсами через их представления (representations — JSON, XML и т.д.)<br>- Самоописательные сообщения (метаданные, заголовки)<br>- **HATEOAS** (Hypermedia as the Engine of Application State) — клиент узнаёт, что можно делать дальше, из ссылок в ответе (это уровень зрелости 3 по Richardson Maturity Model). <br>→ Упрощает и унифицирует API, делает его интуитивным.                                                                                                                                                                                                                                                                                                                                                                                                                   |
| 5. Layered system                       | принцип REST, который говорит: система должна быть разделена на слои, и каждый слой скрывает детали реализации других<br>- **Масштабируемость**: можно добавлять промежуточные слои (например, кэш, балансировщик нагрузки) без изменения клиента.<br>- **Безопасность**: можно вставить слой аутентификации или фильтрации.<br>- **Упрощение**: каждый слой отвечает за свою задачу.<br><br>Представим веб-приложение:<br>1. **Клиент (браузер)** → отправляет HTTP-запрос.<br>2. **API Gateway** (первый слой) → проверяет токен, маршрутизирует запрос.<br>3. **Кэш (например, CDN)** → может вернуть данные без обращения к серверу.<br>4. **Приложение (Backend)** → обрабатывает бизнес-логику.<br>5. **База данных** → хранит данные.<br><br>Клиент не знает, что между ним и сервером есть кэш или балансировщик — он просто отправляет запрос на API Gateway. Это и есть layered system. |
| 6. Code-on-Demand                       | Сервер может передавать клиенту исполняемый код (например, JavaScript), который клиент выполняет для расширения функциональности. → Редко используется в чистом виде в современных API, поэтому часто говорят «5 основных + 1 опциональный».                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |


Основные принципы хорошей архитектуры (по ISO/IEC 25010):
- Масштабируемость (scalability): способность расти с нагрузкой.
- Надежность (reliability): устойчивость к сбоям.
- Поддерживаемость (maintainability): легкость изменений.
- Безопасность (security): защита данных.

## Монолитная архитектура

Монолитная архитектура — это подход, при котором все компоненты приложения (UI, бизнес-логика, база данных) собраны в единую codebase и развертываются как один исполняемый файл или процесс. Это как "один большой кирпич".

Пример: Классический веб-сайт на PHP (например, WordPress) или приложение на Java Spring Boot, где фронтенд, бэкенд и БД интегрированы.

#### Как работает?
- **Структура:** Обычно слои — презентационный (UI), бизнес-логика, данные.
- **Развертывание:** Один сервер, один build.
- **Взаимодействие:** Компоненты вызывают друг друга напрямую (функции/методы).

## Микросервисная архитектура

Микросервисная архитектура — это подход, где приложение разбивается на маленькие, независимые сервисы, 
каждый из которых отвечает за конкретную функцию. Сервисы общаются по сети (API, HTTP, gRPC, message queues).
